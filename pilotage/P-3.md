# P-3 — le ticket de backlog est une fiche

## Reste

- [ ] Trancher : les afficher sur la carte, ou seulement s'en servir pour trier

### Migration
- [ ] Écrire la marche à suivre pour convertir un backlog en prose (mesuré : 39 tickets
      dans un fichier de 363 lignes) en autant de fiches
- [ ] Vérifier sur ce cas que l'écran des chantiers reste lisible à 39 entrées

## Contexte

Un ticket de backlog n'est pas une troisième nature de document : c'est un chantier dont
le travail n'a pas commencé — `Arrêté sur` absent, aucun commit, silence infini. L'écran
le rend déjà tel quel ; c'est vérifié sur un dépôt vide.

L'alternative — un fichier unique portant N tickets — a été écartée le 2026-08-24. Le
couplage « un fichier = un chantier » est pourtant faible (rien n'indexe les chantiers
par fichier, le routage est par code, l'écriture vise fichier + ligne), mais un fichier
multi-tickets impose un second mode de lecture : `##` ne peut plus vouloir dire `Reste`
puisqu'il ouvrirait un ticket. Deux parseurs, donc l'adaptativité par la porte de
derrière.

Le backlog se balaye sur l'écran des chantiers, qui est trié ; le fichier, on l'ouvre
pour en reprendre un.
